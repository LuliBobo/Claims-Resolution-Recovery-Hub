# Order / Shipment / CustomerCase — Exact Import Template (Read-Only Reference)

Generated by reading the live Postgres schema (`information_schema.columns`, `pg_enum`) and the
live spec's backend API definitions directly. Every field name, type, and enum value below is
**VERIFIED** against the deployed workspace — nothing here is invented or carried over from any
earlier proposed/synthetic schema.

## Bulk CSV import — does it exist today?

**No.** Confirmed by inspecting every backend API whose entities include Order, Shipment, or
CustomerCase: all of them are single-record `create`/`update`/`get`/`list` endpoints. None accepts
a list/array field, a file field for these entities, or any batch payload. The only file-type
field anywhere in the spec is `uploadAttachment`'s single `file` (FILE_REF) field, which uploads
one evidence attachment to a case — unrelated to bulk record import. The spec's own text describes
Orders and Shipments as "entered or imported manually," meaning one record at a time through the
Orders/Shipments management pages — there is no parsing, mapping, or ingestion pipeline for a
file today.

**Bulk CSV import would require a new feature** (a new backend API + page/UI to accept a file,
parse rows, validate each against the fields below, and call the existing single-record create
APIs in a loop, or a new bulk-create endpoint). This document does not propose or build that —
it only inventories what exists now, per your read-only request.
